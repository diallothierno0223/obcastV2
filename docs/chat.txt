Super projet 👌 Ça ressemble à une plateforme de valorisation scientifique autour des podcasts.
Comme les données sont principalement qualitatives, il faut penser à un site qui soit à la fois :

un catalogue consultable (métadonnées + descriptif),

un espace d’analyse (graphiques, statistiques),

un outil de recherche et téléchargement (dataset complet ou partiel).

Voici une proposition de structure du site :

🌐 Structure du site
1. Accueil

Présentation du projet (objectif, méthodologie, contexte de recherche).

Mise en avant des partenaires (université, labo, chercheurs).

Accès rapide aux grandes rubriques (podcasts, analyses, téléchargement).

2. Base de données des podcasts

Catalogue consultable avec fiches descriptives :

Titre du podcast / épisode

Auteur / producteur

Date de publication

Thématiques

Résumé analytique (si existant)

Lien d’écoute externe (Spotify, site officiel, etc.)

Filtres et recherche avancée :

Par mot-clé

Par date

Par thématique / genre

Par langue

Affichage : liste + possibilité de vue "carte" ou "grille".

3. Visualisations et analyses

Tableaux de bord interactifs (par ex. avec Plotly ou Chart.js) :

Répartition par thématique

Évolution temporelle (nombre de podcasts par année/mois)

Acteurs les plus présents (producteurs, invités)

Nuages de mots (issus des titres ou résumés)

Possibilité de filtrer les graphiques selon les critères choisis.

4. Téléchargement de données

Téléchargement complet (CSV/JSON/Excel).

Téléchargement partiel :

Choisir un sous-ensemble via filtres (ex : podcasts de 2022 sur l’éducation).

Export au format choisi.

5. Recherche avancée et exploration

Moteur de recherche textuelle (par mots-clés, auteurs, thèmes).

Recherche qualitative (par codage, catégories thématiques, etc. si codage déjà fait).

Navigation par tags ou catégories (cloud de tags interactif).

6. À propos

Équipe du projet.

Méthodologie de collecte et d’analyse.

Licence d’utilisation des données (Creative Commons ?).

7. Espace technique / API (optionnel)

Fournir une API ouverte pour que d’autres chercheurs puissent interroger directement la base.

🔧 Stack technique possible

Front-end : React / Vue + TailwindCSS.

Back-end : Django (Python) ou Node.js (Express).

Base de données : PostgreSQL (souple pour métadonnées + JSON pour qualitatif).

Visualisation : Plotly.js, Chart.js ou D3.js.

Export : CSV / XLSX via API.
